# Прогоны набора

Один каталог на прогон: `evals/results/<YYYY-MM-DD>/`.

| Файл                   | Что это                                                                                        |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| `summary.md`           | матрица провайдер × результат, что изменилось с прошлого раза, разбор упавших кейсов           |
| `results.json`         | машинный вывод promptfoo (`--output`): каждый ответ модели, каждая ассерция, токены, стоимость |
| `promptfoo-output.txt` | сырой stdout прогона — таблица и итоговая строка, как их видел терминал                        |

## Зачем это в git

`~/.promptfoo/promptfoo.db` живёт на одной машине, чистится и не переживает
смену ноутбука. Вопрос «стало лучше или хуже после правки промпта» требует
предыдущей точки отсчёта, а она нужна в репозитории — рядом с тем коммитом
промпта, который её произвёл. Каталог с датой в имени и есть эта точка.

Прогон не воспроизводится байт в байт: модели недетерминированы даже на
`temperature: 0.2`, и цены на OpenRouter меняются. Поэтому сохраняется
результат, а не обещание его повторить.

## Как добавить новый

```sh
export OPENROUTER_API_KEY=...
mkdir -p evals/results/$(date +%F)
npx promptfoo eval --config evals/promptfooconfig.yaml \
  --output evals/results/$(date +%F)/results.json \
  | tee evals/results/$(date +%F)/promptfoo-output.txt
```

Затем `summary.md` — руками, по шаблону предыдущего.
