# Тест-фикстуры для оценки агента код-ревью

Шесть диффов в формате `git diff` плюс `.expected.md` рядом с каждым — основа ассерций.

| Фикстура                       | Что внутри                                                                       | Критерий из `context/review-criteria.md` |
| ------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------------- |
| `01-filename-cap-byte-claim`   | выглядит чисто: комментарий обещает 255 байт, обрезка идёт по символам           | 5. Слой, дубли и стоимость чтения        |
| `02-zod-migration-drift`       | zod поднял лимит комментария, check-констрейнт в миграции — нет                  | 1. Синхронность контрактов               |
| `03-cv-tags-missing-rls`       | новая таблица `cv_tags` без RLS и без политик                                    | 4. Доказанная граница доступа            |
| `04-vacuous-generate-test`     | тест ассертит собственный мок и `toBeDefined()`                                  | 3. Тест, который может упасть            |
| `05-prompt-warning-code-drift` | промпт эмитит `date_gaps`, zod-энум его не знает, фикстура не обновлена          | 1 + 3                                    |
| `06-salvage-partial-draft`     | «починка» невалидного драфта вместо честной ошибки — выглядит как UX-фикс        | 2. Честный отказ                         |
| `07-clean-cv-notes-table`      | по-настоящему чистый PR: новая таблица с RLS, политиками и pgTAP-доказательством | — (ожидается пустой результат)           |

## Как подавать агенту

Каждый файл начинается с блока `Subject:` / `Description:` — это title и body PR,
то есть ровно тот вход, который описан в `context/changes/ci-cd-code-review/requirements.md`.

**Всё после строки `--- FIXTURE METADATA (strip before feeding the agent) ---` нужно
отрезать перед подачей** — там лежит ответ (какой критерий нарушен). Маркер одинаковый
во всех шести файлах, включая чистый, чтобы по наличию блока нельзя было угадать.

```sh
sed '/^--- FIXTURE METADATA/,$d' evals/fixtures/02-zod-migration-drift.diff
```

## Оговорки

- Диффы написаны как вход для ревьюера, а не для `git apply`: хеши в строках `index`
  выдуманы, номера строк приблизительны, преамбула и футер сломают применение патча.
- Фикстуры 02, 03 и 05 требуют контекста за пределами диффа (текущая миграция, соседние
  таблицы, zod-энум, содержимое тестовой фикстуры). Если агент получает только
  title + description + diff, он их не поймает — это осознанная проверка того, достаточно ли
  такого входа.
- Все резюме и имена в примерах выдуманы; персональных данных нет.

## Кто здесь «чистый»

Роль чистой фикстуры играет **07**, а не 01. До 2026-08-27 её играла 01, но в её диффе
есть настоящий дефект: комментарий обещает запас по 255-байтному лимиту, которого
посимвольная обрезка не даёт. На прогоне 2026-08-27 opus-4.8 это нашёл и был засчитан
как провалившийся — набор наказывал внимательную модель. 01 переведена в разряд
«выглядит чисто, но не чисто», 07 заведена как страховка от ложных срабатываний.
